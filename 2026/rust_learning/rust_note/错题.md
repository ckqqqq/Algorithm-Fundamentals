*   第一幕：送出去（move）
        你朋友阿强说："把吉他给我吧，我来调音。"

        你把吉他递到他手里——注意，是真的递过去了，你两手空空了。

        string_uppercase(data);   // data 就像吉他，整个递过去
        从这一刻起：

        吉他是他的了，他想换弦换弦，想喷漆喷漆；
        你要是想弹——低头一看，手里没了。assert_eq!(vec0, ...) 报错就是你在空手弹空气；
        他调完如果人好，会还你一把（-> Vec<i32>），那是新的归属关系，跟你原来那把已经不是同一把了。
    第二幕：借看看（&）
        另一个朋友阿珍说："我就看看琴头上的签名，拍张照。"

        get_char(&data);   // & = "我就看看"
        吉他没离开你的手，她只是凑过来看。

        她能看、能拍照（chars().last()），但不能换弦——琴不在她手里；
        看完你接着弹，什么都不影响；
        关键点：因为她只看看，所以你可以同时让十个人围观——& 可以有无数个。
    第三幕：借去改（&mut）
        还有个小明："借我一下，我帮你拧紧弦钮，马上还。"

        let y = &mut x;
        吉他还是你的（所有权没动），但他手里握着琴在拧——这时候铁律来了：

        琴在谁手上拧的时候，别人都得退后。

        &mut 同一时刻只能有一个。你不能让小明拧着弦钮、阿珍同时凑上去拍照——琴会出事。这就是 let z = &mut x; 报错的原因：琴只能一双手碰，要么很多人看，要么一个人改。

*    更深的追问：为什么 Rust 要搞两个字符串类型？
        因为零成本抽象的执念：

        如果所有字符串都是 String，那每次写 "blue" 都得堆分配——哪怕你只是临时看一眼。浪费；
        &str 让你能"借用"任何字符串数据（字面量、别人的 String 的一部分、网络缓冲区）而不付任何拷贝成本；
        只有当数据真的需要"归你所有、随你带走、能活过函数返回"时，才用 String。
        这就是为什么函数的返回类型通常是 String（返回值要活着离开函数，不能借），而参数类型通常是 &str（调用者给什么都能借给你看）：
*   串回你的 codex 阅读
        codex 每个 crate 的 lib.rs 里都有一堆 pub use，把内部精选的类型提到 crate 门面——比如 codex_core 把深处模块的 CodexThread re-export 出来，让使用者不用记内部文件结构。读 crate 先看 lib.rs 的 pub use 列表，就是这个 crate 自认为的"公共形象"。
        一句话总结这题：use 是给自己用的进口，pub use 是给用户设计的货架——as 负责让货架标签比仓库编号更好读。
